Detailed Description

Class responsible for holding and managing modules.

Modules are loaded into a ModuleManager in two ways: as part of a plugin (see load_plugin), or one at a time (see add_module). The ModuleManager keeps one ModuleMap per loaded plugin, plus a ModuleMap of its own for the modules that do not come from a plugin. The empty plugin name, "", refers to the ModuleManager's own modules.

Plugin names and module keys are case-insensitive. Module keys are unique within a map, but two maps may use the same key. Functions that take a module accept a QualifiedKey. A plain module key works as long as exactly one map has that key; otherwise the plugin name must be given too, e.g., mm.at({"integrals", "Overlap"}).

Changes the submodule a module calls.

Modules can call other modules at predesignated callback points. Each of these callback points has a key associated with it. This function allows the user to change which module is called at a particular callback point by specifying the key of the module, the callback point's key, and the key for tne new submodule.

Parameters
[in]module_keyThe module whose submodule is being changed.
[in]callback_keyThe name of the callback point in the module assigned to module_key
[in]submod_keyThe submodule to call. It may be in a different map than module_key.
Exceptions
std::out_of_rangeif any of the keys do not refer to valid, already present modules or callback points. Weak throw guarantee.
std::invalid_argumentif module_key or submod_key is ambiguous. Strong throw guarantee.

Makes a "deep copy" of a module.

This function will copy the module stored under old_key and store the copy under new_key. The copy will be unlocked, with a deep copy of old_key 's inputs and submodules. Deep copy in this context meaning that changing new_key 's inputs or submodules will not affect the module stored under old_key.

The copy is always stored in *this's own map (plugin name ""), even if old_key is one of a plugin's modules. Plugins' maps only hold the modules the plugins provide.

Parameters
[in]old_keyThe module which is being copied.
[in]new_keyThe key for the resulting copy.
Exceptions
std::out_of_rangeif old_key does not refer to a module. Strong throw guarantee.
std::invalid_argumentif old_key is ambiguous or *this's own map already has a module with key new_key. Strong throw guarantee.
std::bad_allocif an allocation error arises.

◆ load_plugin() [2/2]

void pluginplay::ModuleManager::load_plugin ( plugin_pointer  plugin)

Loads plugin.

*this takes ownership of plugin and its modules. Nothing is copied: the plugin's ModuleMap is the map this uses for the plugin's modules. Each module is given *this's runtime and caches. A plugin's modules use the module cache named "<plugin name>::<module key>". Modules that are reachable through submodules, but no longer in the plugin's map (*e.g., the plugin erased them after using them as submodules), are given the runtime and caches too, using the key they were last stored under.

Loading does not set default submodules between plugins; call wire_defaults after all plugins are loaded.

Parameters
[in]pluginThe plugin to load. If this function throws, the plugin is destroyed.
Exceptions
std::invalid_argumentif plugin is null, has no name, or has the same name as a loaded plugin. Strong throw guarantee for *this.
std::bad_allocif there is a problem allocating the caches. Weak throw guarantee.

◆ wire_defaults()

void pluginplay::ModuleManager::wire_defaults ( )

Sets default submodules between the loaded plugins.

For each loaded plugin, in load order, and for each of its preferred providers that is loaded, in priority order, this applies the default submodules the plugin recorded for that provider (see Plugin::default_submod_from). A default only sets a submodule that is still unset, so choices made by the user, or by a provider with higher priority, are kept. Defaults that name a module the provider does not have are skipped, with a warning through the runtime's logger.

Calling this function again, e.g., after loading another plugin, only fills submodules that are still unset.

Exceptions
std::runtime_errorif a provider's module does not satisfy the property type of the submodule. Weak throw guarantee.
