Detailed Description

What a driver sets on the modules below it.

A CallGraphRequest is an ordered list of wiring requests (see WiringRequest), plus the conditional chains (see ConditionalWiring), the default modules of the driver's submodules, and the memoization policy of a driver. It is data: it names its targets by key and resolves nothing itself. The ModuleManager resolves it when the driver is locked.

A driver has two requests:

  • the developer's, filled in the driver's constructor through DriverBase, DriverInput, and DriverSubmodule; and
  • the user's, returned by Module::call_graph_request(), to which the user may only add fixed values, with set_input and set_submod.

The user's requests are applied after the developer's, so they win.

A request is locked while the driver holding it is, i.e., once the driver has run. Changing a locked request throws, since the driver's requests are only resolved before it locks.
